# Accuracy and performance protocol

The public reference source is google/fleurs (English en_us and Arabic ar_eg, test split, CC-BY-4.0). Use `NODE_USE_ENV_PROXY=1 node scripts/import-fleurs.mjs .local/fleurs` to obtain public audio and its human-produced references. Keep downloaded assets ignored. If the rows service fails, use `python scripts/import-fleurs.py .local/fleurs 2 70bb2e84b976b7e960aa89f1c648e09c59f894dd` for the pinned streaming archive fallback. Dataset service availability is not guaranteed: failed acquisition is an unverified accuracy gate, never a passing test. Record repository revision and immutable downloaded file hashes before comparing runs. Never tune on these held-out fixtures. Human spot checking and domain/code-switching references remain separate gates.

`node scripts/benchmark-desktop.mjs manifest.json report.json 3` runs an offline manifest. Profiles contain actual processing settings, fixtures reference local authorized audio. Reference text is scored only when explicitly marked referenceVerified. Reports exclude hypothesis text, contain strict/normalized WER/CER, source hashes, RTF and recovery costs. Arabic normalization removes diacritics/tatweel, folds alef variants and alef maqsura; it retains ta marbuta, numbers and negations. It is reported separately from strict scoring. Silence with no reference has no fabricated WER.

Evaluate cold process/model starts and warm repeated worker requests separately. Initial screening uses short fixtures; shortlist thread counts and chunk sizes before three repetitions of long recordings. GPU/device support requires actual hardware evidence. Peak native process-tree RAM/VRAM and UI p95 are not available from Node's RSS and must not be substituted by it.

Private recordings and proposed terminology edits are not ground truth. Context ablations require human references and include wrong PDF, contradictory values/negation, absent terms, OCR errors and speech absent from slides. An automated structural pass cannot prove lexical correctness.
